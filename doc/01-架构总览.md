## 分层设计

```
┌─────────────────────────────────────────────────┐
│  lib/ui/        Flutter GUI（Android/Windows/Linux） │
│  lib/tui/       终端交互界面                        │
│  lib/cli/       命令行入口                          │
├─────────────────────────────────────────────────┤
│  lib/platforms/  平台装配：更新器选择、Android 原生桥 │
├─────────────────────────────────────────────────┤
│  lib/core/      纯 Dart 核心（三种界面共用）          │
│    config/   配置模型与读写                        │
│    github/   Release 获取（API / 直链）            │
│    matcher/  资产匹配规则                          │
│    download/ 下载管理（多线程/断点续传）            │
│    updater/  更新编排（检测/下载/安装）             │
│    version/  版本解析与比较                        │
│    platform/ 平台能力抽象（bridge / android_env）   │
│    scheduler/后台自动检测调度                       │
│    log/      日志                                  │
└─────────────────────────────────────────────────┘
         │ MethodChannel（grku/native）
         ▼
  android/app/src/main/kotlin/.../MainActivity.kt
```

- **core 不依赖 Flutter**：GUI、CLI、TUI 共享同一套业务逻辑；CI 的静态分析对 core 同样生效。
- **platforms/ 负责"组装"**：`updater_registry.dart` 按当前平台选出可用的 `Updater` 列表注入 `UpdateService`；`flutter_android_env.dart` 把 MethodChannel 封装成 `AndroidEnv` 接口实现。
- **原生层只做 Flutter 做不到的事**：权限申请、签名读取、静默安装、模块刷入、应用启动等。

## 一次更新的完整数据流

```
配置加载
  main.dart → setAppBaseDir / setConfigPathOverride（Android 路径决策）
  configRepoProvider → ConfigRepository.load()
      ├── config.yaml  软件配置（token/间隔/通知/镜像/…）
      └── repos.yaml   仓库配置（RepoConfig 列表）

后台/手动检测（checkOne）
  UpdateService.check(repo)
      ├── ReleaseFetcher.getLatest()      ← GitHub API，失败回退直链
      ├── AssetMatcher.match()            ← 按 平台+策略+架构+正则 选资产
      └── resolveInstalledVersion()       ← 已装版本（系统 API / module.prop / 版本文件）
  → _persistAfterCheck（记录检测时间/已装 tag）
  → _learnIdentity（反查 packageName / moduleId）
  → _fillApkInfo（补全名称/图标/分类标记，见 04 篇）

下载与安装（updateOne）
  UpdateService.update(check)
      ├── DownloadManager.download()      ← 多线程/断点续传，CancelToken 可中断
      ├── 校验和（可选，sha256/md5）
      ├── onDownloaded 回调               ← 安装前提取 APK 信息（失败也能提取）
      └── Updater.apply()                 ← 按策略分发：
            WindowsUpdater  portable 解压覆盖（保留数据）/ installer 静默安装
            LinuxUpdater    portable / AppImage / docker 重建
            AndroidUpdater  APK（root / Shizuku / 系统安装器）/ 模块刷入（ksud/magisk/apd）
  → 写版本记录文件 / lastInstalledTag
```

## 设计约定

- **StateNotifier.state 是 protected**：外部需要当前配置时用 `ref.read(configProvider)` 传快照，或用 `ConfigNotifier.freshRepo(r)` 取最新仓库条目再做增量修改（避免旧快照覆盖并发写入的字段）。
- **写入原子化**：`ConfigRepository._writeLocks` 按路径串行化，临时文件 + rename。
- **Dart RegExp 不支持 `(?i)`**：大小写兼容用字符类（`[Zz]`）。
- **版本比较一律用 `versionMatchesTag`**：兼容 `v` 前缀与 LSPosed 仓库的 `versionCode-versionName` tag 格式（详见 03 篇）。
