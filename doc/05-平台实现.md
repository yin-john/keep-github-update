# 05 · 平台实现

[← 返回目录](README.md)

## 平台桥接（`lib/core/platform/bridge.dart`）

`PlatformBridge` 抽象桌面端与 Android 的共性能力：解压 / APK 安装 / 模块刷入 / docker / 系统通知 / `openExternal` / `launchPortableApp` / Android 包版本表（`androidPackageVersions`，dumpsys 解析）等。`DefaultPlatformBridge` 为默认实现。

## Android 原生层（MethodChannel `grku/native`）

实现在 `android/app/src/main/kotlin/.../MainActivity.kt`，Dart 侧封装为 `AndroidEnv` 接口（`lib/core/platform/android_env.dart`）：

- GUI：`FlutterAndroidEnv`（MethodChannel 实现，`lib/platforms/flutter_android_env.dart`）
- CLI/TUI：`ShellAndroidEnv`（root / Shizuku shell，能力有限是设计使然）

### 主要方法

| 方法 | 说明 |
|---|---|
| `has/requestStoragePermission` | 存储权限（Android 11+ 为所有文件访问） |
| `has/requestNotificationPermission` | 通知权限（Android 13+） |
| `has/requestRoot`、`has/requestShizuku` | root（su）/ Shizuku 授权 |
| `apkSignature` / `installedSignature` | APK 与已装应用的签名摘要（SHA-256），安装前比对 |
| `apkAppInfo(path)` | 读 APK 的名称/图标/包名/版本/**Xposed 标记** |
| `installedAppInfo(pkg)` | 读已装应用的同上信息 |
| `installedVersion(pkg)` / `isLaunchable(pkg)` | 已装版本；是否有启动入口（XP 模块视为可启动） |
| `launchApp(pkg)` | 启动应用；XP 模块先尝试 LSPosed 管理器，失败回退直接启动 |
| `selfPackageName` | 自身包名（「自己更新自己」识别，避免误卸载自身） |
| `startBackgroundService` 等 | 前台服务保活 + 常驻通知（`BackgroundService.kt`） |

### Xposed 模块识别（`isXposedApp`，双判定）

1. **旧式**：`xposedmodule` 元数据（需 `GET_META_DATA` 读取）——LuckyTool 等老模块；
2. **新式**：ZipFile 检查 APK 内 `META-INF/xposed/java_init.list` 或 `module.prop`——libxposed API 模块（如 PureDuPan）manifest 无任何 xposed 元数据，只认这个标记。

> 提取到的标记持久化为 `RepoConfig.xposedModule`，供分类分栏使用；缓存由「提取器版本标记」管理（见 04 篇），检测逻辑升级后旧缓存会自动重提取。

### 模块刷入要点

`flashModule` 用 `Process.start` 流式执行，依次尝试 `ksud` / `magisk` / `apd` 及绝对路径兜底；**shell 引号只转义一次**（`_quote()` 已生成单引号包裹，外面不要再包——曾导致模块刷入必败）。

## Windows / Linux 更新器

`lib/platforms/` 下 `windows/linux updater`（经 `PlatformBridge`）：

- portable：解压覆盖 + 数据保留 + 写版本记录文件（`grku_version.txt`）
- installer：静默安装（exe `/S`、msi 走 msiexec，`installArgs` 追加）
- AppImage / 单文件：直接替换
- docker：拉镜像重建容器

## 后台调度（`lib/core/scheduler/`）

- `UpdateScheduler`：按「全局间隔 + 仓库级覆盖」的最近时刻调度静默检测；GUI 由 `AppShell` 在启动/配置变更时 start/stop。
- Android：前台服务常驻，通知显示下次检测时间；桌面端开启保活后关窗不退出。
- 检测触发 `checkMany`，与手动检测共用同一份状态（`checkProvider`），发现更新按 `notificationsEnabled` 发通知。
