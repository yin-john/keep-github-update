# 04 · 下载与更新编排

[← 返回目录](README.md)

## 下载管理（`lib/core/download/download_manager.dart`）

- **多线程分块**：`downloadThreads > 1` 时按 Range 分块并发，服务器不支持时自动回退单线程。
- **断点续传**：`.part` / `.resume` 状态文件；中断后继续。
- **可中断**：Dio `CancelToken`，GUI「暂停」按钮与下载列表都走它。
- **完整性校验**（可选）：`checksum.dart` 支持 sha256 / md5；自动按「产物名 + 扩展名」推断校验文件，或由 `checksumRegex` 指定。

## 更新编排（`lib/core/updater/update_service.dart`）

```dart
class UpdateService {
  Future<UpdateCheck>   check(repo);            // 检测：fetch + match + 已装版本
  Future<UpdateCheck>   checkRelease(repo, release);
  Future<List<Release>> listReleases(repo);     // 「更多版本」页
  Future<UpdateIdentity?> detectIdentity(repo, tag);   // 反查包名/模块 ID
  Future<String?>       resolveInstalledVersion(repo);
  Future<File>          update(check, {onDownloaded, cancelToken, dryRun});
}
```

- `update()` 流程：镜像改写 URL → 下载（可中断）→ 校验 → **`onDownloaded` 回调（安装前触发，安装失败也能提取 APK 信息）** → `Updater.apply()` → 写版本记录。
- 已装版本解析优先级（`resolveInstalledVersion`）：Android 模块 `module.prop` → APK 系统 API（`androidEnv.installedAppVersion`，无需 root）→ 设备包版本表反查 → 便携目录版本记录文件 → `lastInstalledTag`。
- 安装器列表在 `lib/platforms/updater_registry.dart` 按平台装配。

## 安装策略实现

| 策略 | 平台 | 实现 |
|---|---|---|
| `portable` | Win/Linux | 解压覆盖安装目录；`preservePaths` / `preserveFiles` 正则匹配的数据在覆盖时保留；写 `grku_version.txt` |
| `installer` | Windows | exe `/S` 静默安装（`installArgs` 可扩展）；msi 走 msiexec |
| `docker` | Linux | 拉取镜像并按 `containerName` / `dockerRunArgs` 重建容器 |
| `apk` | Android | root 静默安装 / Shizuku / 系统安装器；签名校验，可实验性无视签名 |
| `module` | Android | 模块 zip 刷入：依次尝试 ksud / magisk / apd 及绝对路径兜底，统一追加 PATH；输出走 `ModuleInstallConsole`（broadcast stream + 日志），GUI 有终端窗口 |

## APK 信息提取与缓存（`lib/core/platform/apk_local_info.dart`）

产物落在仓库下载目录：图标 `app_icon.png`、信息 `app_name.txt`（名称/包名/版本/Xposed 标记/提取器版本，每行一项）。

提取优先级（`_fillApkInfo`，GUI 侧 `check_providers.dart`）：

1. **本地已下载的 APK** → `extractApkInfoIntoDir`（原生 `apkAppInfo` 读取）；
2. **本地无 APK 且已装版本与仓库最新一致** → 从**已安装的应用**提取（`installedAppInfo`），无论是否曾下载过；
3. 缓存命中（`app_name.txt` + `app_icon.png` 均比 APK 新）→ 直接解析复用，不调用原生。

缓存失效规则（`_cachedResult`）：

- APK 比缓存新（刚更新过）→ 重提取；
- 结构化文本缺「`Xposed 模块:`」行或「`提取器: v2`」标记 → 视为旧版提取器产物，**强制重提取一次**（检测逻辑升级时递增该标记即可让所有旧缓存失效）；
- 旧版单行纯名称格式不受影响（兼容读取）。

提取到的信息写回仓库配置（`_applyApkInfo`，无变化时不写盘）：`apkLabel` / `apkIconPath` / `packageName`（自动补全）/ `downloadedVersion` / `xposedModule`。

## 仓库分类（分类分栏用，`RepoConfig` getter）

| 分类 | 判定 |
|---|---|
| Magisk/KSU 模块 | `isMagiskModuleRepo`：`assetRules` 含 `module` 策略 |
| LSPosed 模块 | `isXposedModuleRepo`：`isApkRepo && xposedModule`（元数据或 `META-INF/xposed/` 标记，见 05 篇） |
| 普通应用 | `isNormalAppRepo`：其余 |

`xposedModule` 标记在 APK 下载/信息提取时自动学习，持久化于 `repos.yaml`；旧仓库升级后首次检测自动补齐（缓存代际机制保证重提取）。

## 安装重试

下载成功但安装失败时，检测状态带 `canRetryInstall`；「重试安装」直接复用已下载文件，无需重新下载。
