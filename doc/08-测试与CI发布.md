## CI 工作流（`.github/workflows/ci.yml`）

| Job | 内容 |
|---|---|
| `test`（windows-latest） | `flutter analyze`（**零容忍**，任何 info 都算失败）+ `flutter test`，timeout 20min |
| `build-windows` | GUI + CLI（CLI 用 `dart compile exe --define=GRKU_VERSION=<pubspec 版本>` 注入版本） |
| `build-android` | ubuntu-24.04 + JDK 21 + 签名 secrets；分 ABI + 通用包；会把 gradle-wrapper 腾讯镜像改回官方源 |
| `release`（仅 main） | 按 `pubspec.yaml` 版本打 tag `vX.Y.Z`，`gh release create --generate-notes`；**同版本 tag 已存在则跳过** |

## 版本与发版规则

1. **版本号唯一来源**：`pubspec.yaml` 的 `version`（`x.y.z+build`）；每次发版同步改 `lib/core/version/app_version.dart` 的 `appVersionDefault`（有测试保证一致），build 号递增。
2. 标准流程：**改动 → 新分支 push → `gh pr create` → PR 上 CI（analyze + test）→ 通过后合并 main → main 自动构建并按版本发 Release**。
3. 读 CI 日志：`gh pr checks <n>`、`gh run list`、`gh run view <run-id> --log-failed`。
4. 用户在国内：不要用 `gh` 下载 release 产物（慢/失败），需要产物让用户自行下载。
