# 02 · 配置体系

## 文件布局（configVersion = 4）

| 文件 | 内容 |
|---|---|
| `config.yaml` | 软件配置：token、检测间隔、通知、Webhook、镜像、下载线程数、日志开关等 |
| `repos.yaml` | 仓库配置：`RepoConfig` 列表（含资产规则、已装版本等） |

- 两文件**同目录**、均为 v4；启动时自动检测旧版单文件配置（v1–v3，软件配置里带 repos）→ 自动拆分转换，原文件备份为 `config.yaml.bak`（仅首次）。迁移逻辑：`ConfigRepository._migrateLegacy`。
- **导入/导出**仍是单个合并文件（便于分享）；导入旧版文件同样自动转 v4。测试：`test/config_v4_test.dart`、`test/config_export_test.dart`。

## 存储路径策略（`lib/core/config/app_paths.dart`）

| 平台 | 配置 | 下载 | 日志 |
|---|---|---|---|
| Windows | `%APPDATA%\github_releases_keep_update\` | 同左 `downloads\` | 同左 `logs\` |
| Linux | `$XDG_CONFIG_HOME/github_releases_keep_update/` | 同左 | 同左 |
| Android | `<外部存储>/grku/config.yaml`（公共存储） | `<外部存储>/grku/downloads/` | `<外部存储>/grku/logs/` |

- **Android 启动决策**：`main.dart` 调 `resolveAndroidConfigPath()` 探测公共存储可写性——
  - 可写 → 把私有目录里的旧配置**复制**过去（保留私有副本兜底，不删除），使用公共路径；
  - 不可写（无「所有文件访问」权限）→ 回退私有目录 `fallbackConfigPath()`。
- 日志/下载目录有各自的 fallback 机制（`fallbackDownloadDir` / `fallbackLogDir`）。
- `GRKU_CONFIG` 环境变量可覆盖配置路径（CLI 场景）。
- Android 的仓库下载子目录约定：`<基准下载目录>/<作者名>@<repo名>`（`repoDownloadDir`）。

## 核心模型（`lib/core/config/models.dart`）

### AppConfig（软件配置，节选）

| 字段 | 说明 |
|---|---|
| `githubToken` | PAT，提高速率限制 / 访问私有仓库 |
| `checkIntervalMinutes` | 全局检测间隔（分钟），0 = 关闭自动检测 |
| `systemNotificationsEnabled` / `webhook` | 系统通知总开关；Webhook（URL + 触发事件） |
| `mirrors` | 镜像列表（prefix / regex 两种改写模式），用于加速下载 |
| `downloadThreads` | 下载线程数（1 = 单线程断点续传） |
| `defaultApkInstallMethod` / `forceInstallIgnoreSignature` | APK 静默安装默认授权方式；签名不一致时强制安装（实验性） |
| `loggingEnabled` | 操作日志开关 |

### RepoConfig（单仓库，节选）

| 字段 | 说明 |
|---|---|
| `owner` / `repo` / `tagFilter` | 仓库定位与 tag 过滤 |
| `assetRules` | `AssetRule` 列表（平台 + 策略 + 架构 + 文件名正则 + 校验配置） |
| `notificationsEnabled` | 有更新时是否发系统通知（GUI 编辑页可开关） |
| `checkIntervalMinutes` | 仓库级检测间隔覆盖（null = 跟随全局） |
| `packageName` / `moduleId` | Android：已装应用包名 / 模块 ID（可自动反查补全） |
| `displayName` / `apkLabel` / `apkIconPath` | 自定义名称 / 自动获取的名称与图标 |
| `downloadedVersion` / `lastInstalledTag` / `lastCheckedAt` | 版本追踪 |
| `xposedModule` | 是否为 Xposed 模块（分类分栏用，见 04 篇） |
| `installDir` / `launchFile` / `launchCmd` | 桌面端：安装目录与启动入口 |

`AssetRule.strategy`（更新策略）：`portable`（解压覆盖）/ `installer`（Windows 静默安装）/ `docker`（Linux）/ `apk`（Android 安装）/ `module`（Magisk/KSU 刷入）。平台可用策略见 `PlatformTypeX.strategies`。

## 设置页草稿机制（`lib/core/config/settings_draft.dart`）

GUI 设置页**所有修改先进草稿，点「保存」才写入**：

```
UI 控件 → SettingsDraft.patch()   （内存草稿，dirty = true）
「保存」→ draft.commitTo(provider 最新配置)   （repos 取最新值，防覆盖仓库列表）
        → ConfigNotifier.setConfig(committed)  （写盘 + 通知监听者）
```

- AppBar「保存」按钮带未保存圆点；返回时若有未保存修改会弹确认。
- 导入配置是显式动作：`_draft.reset(cfg)` 直接以导入结果为新基准。
- 日志开关的副作用（`AppLog.configure`）在保存时应用，而非切换时。

## 读写细节

- `_writeLocks` 按文件路径串行化写入；写入走**临时文件 + rename**（原子）。
- `ConfigRepository` 单例由 `configRepoProvider` 提供；GUI 通过 `configProvider`（StateNotifierProvider）读写，`updateRepo` / `setConfig` / `reload` / `clearRepos` 等方法见 `app_providers.dart`。
